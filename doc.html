Okalit Framework

A progressive Web Components framework built on Lit 3, with TC39-proposal Signals via @lit-labs/signals, modern TC39 decorators, and modular architecture.

Lit 3
Incremental template rendering
Signals
Tracked component dependencies
Native
Web Components standard

Key Principles

  • Signals with Lit — SignalWatcher tracks signals read during rendering and schedules component updates. Lit patches dynamic template parts without a virtual DOM.
  • Standards-first — Built on native Custom Elements (Lit). Works in any HTML page, alongside any framework.
  • TC39 Decorators — Clean, declarative component definitions using Stage-3 decorators.
  • Enterprise Architecture — Opinionated App → Module → Page hierarchy with dependency injection, routing, and global state channels.

Manual Setup

Terminal
npm install @okalit/core@^0.3.0 lit@^3.0.0

Okalit requires a build tool that supports TC39 decorators (Stage 3). Recommended: rsbuild, vite, or esbuild with the decorators plugin.

lit is a peer dependency; @lit-labs/signals is installed by the core. Import signal, computed, effect, and html from @okalit/core. No uhtml dependency is required. These instructions target the 0.3.0 source line; registry installation requires that release to be published.

Migrating to Core 0.3.0

This is a breaking change from the 0.2.x line. Version numbers here refer to @okalit/core, not the independently versioned CLI or component library.

Existing application (after 0.3.0 is published)
npm uninstall uhtml
npm install @okalit/core@^0.3.0 lit@^3.0.0
  • Remove uhtml only if no other code in your application uses it. Regenerate and commit your package manager's lockfile; changing a manifest alone does not replace an older resolved core.
  • Use Okalit's html export for Lit templates. Move remaining uhtml imports to Lit equivalents; an old template or directive is not made compatible by changing the package version.
  • Keep .value for signals and props. Computed signals are read-only. Signal wrappers no longer modify the global Signal prototypes.
  • Remove batch imports and calls. It is no longer exported; the previous helper did not implement transactions. Normal Lit update scheduling and effect microtasks still apply.
  • Declare public inputs only through @defineElement({ props }). Lit's static properties and property decorators are not supported. Do not redeclare a decorated prop as an instance field.
  • Read component channel handles in onConnected() (or the compatibility hook onInit()), never in constructors or eager field initializers. Callbacks for stateful channels can run immediately during connection.
  • Pair connection setup with onDisconnected() cleanup. A DOM disconnection is not proof of permanent destruction. See lifecycle rules and form disposal.
  • Routes are removed by default. Opt into cache: true to retain a page instance; use onCacheHide()/onCacheView() to pause and resume work.

The updated local CLI templates and update command no longer request uhtml and target the new core line. Use a CLI release containing those changes when generating projects. The updater does not automatically remove an existing uhtml declaration or migrate application code. A vendored source copy must also be synchronized; if it imports Signals directly, its application's manifest must declare @lit-labs/signals directly.

Okalit Base Class

All Okalit components extend the Okalit class, which extends Lit's LitElement with signal reactivity, channels, and lifecycle hooks.

my-component.js
import { Okalit, html, defineElement } from '@okalit/core';
import styles from './my-component.scss?inline';

@defineElement({
  tag: 'my-component',
  styles: [styles],
  props: [
    { count: { type: Number, value: 0 } },
    { label: { type: String, value: 'Hello' } },
  ]
})
export class MyComponent extends Okalit {
  onConnected() {
    // Called when component connects to DOM
  }

  render() {
    return html`
      <p>${this.label.value}: ${this.count.value}</p>
      <button @click=${() => this.count.value++}>+1</button>
    `;
  }
}

Key Concepts

  • Props are signals — access with .value, set with .value = x
  • SignalWatcher(LitElement) tracks signal reads during rendering and requests Lit updates when dependencies change
  • Styles use CSSStyleSheet (Adopted Stylesheets) — shared across all instances of the same component
  • Shadow DOM is enabled by default (inherits from LitElement)

@defineElement Decorator

Registers your class as a Custom Element and configures its styles, props, and observed attributes.

Signature
@defineElement({
  tag: string,           // Custom element tag name (must contain a dash)
  styles?: string[],     // Array of CSS strings (use ?inline imports)
  props?: PropDef[],     // Reactive property definitions
})

Props Definition

Each prop is an object with a single key (the prop name) mapping to its config:

Props Config
props: [
  { myProp: { type: String, value: 'default' } },
  { count:  { type: Number, value: 0 } },
  { active: { type: Boolean, value: false } },
]
FieldTypeDescription
typeString | Number | BooleanUsed for attribute coercion from HTML
valueanyInitial default value for the signal

Prop names are automatically converted to kebab-case for HTML attributes: myProp → my-prop.

Signals & Reactivity

Okalit wraps the TC39-proposal Signals implementation provided by @lit-labs/signals. These are proposal-based APIs, not a required native browser feature. The wrappers preserve .value without modifying global prototypes.

Imports
import { signal, computed, effect } from '@okalit/core';

signal(initialValue)

Creates a reactive atom. Read and write with .value.

Example
const count = signal(0);
console.log(count.value); // 0
count.value = 5;         // triggers dependent effects/renders

computed(fn)

Creates a read-only derived signal. Its value is recomputed lazily when read after a dependency changes; do not assign to its .value.

Example
const doubled = computed(() => count.value * 2);
console.log(doubled.value); // 10

effect(fn)

Runs immediately, then reruns after dependency changes in a microtask. Returns a dispose function. If the callback returns a cleanup function, it runs before the next execution and on disposal. User-created effects are not automatically owned by the component: store and call their disposers.

Example
const dispose = effect(() => {
  console.log('Count is:', count.value);
});

// Stop tracking:
dispose();

Signals in Components

Props declared in @defineElement are automatically wrapped in signals. SignalWatcher tracks reads during rendering. An update can execute the component's render() again; Lit updates its existing template parts rather than replacing the entire container.

Automatic tracking
render() {
  // Reading this.count.value registers this component
  // as a subscriber of the count signal
  return html`<p>${this.count.value}</p>`;
}

Preserving DOM and child state

  • A stable template normally retains existing input and child-element nodes. Re-running render() is not the same as destroying the subtree.
  • A local child signal does not automatically update its parent or siblings. Components reading a shared signal each become its dependents.
  • Removing a conditional branch, changing a keyed identity, or explicitly replacing DOM can destroy nodes. Use repeat from lit/directives/repeat.js with stable item keys for reorderable lists.
  • Bound input properties can still overwrite user input. Fresh arrays/objects passed on every render can trigger extra child updates. Keep object identities stable when their contents have not changed.

Lifecycle Hooks

Okalit provides clean lifecycle hooks that wrap Lit's internal callbacks:

HookWhen it runs
onConnected()Every DOM connection, after attribute synchronization and channel initialization. Rendered children may not exist yet.
onInit()Compatibility hook called by the default onConnected(); not a once-only constructor hook.
onChange(changes)When any prop signal value changes. Receives { propName: { previous, current } }
onBeforeRender(changedProperties)Before each render cycle (willUpdate)
onFirstRender(changedProperties)After the very first DOM render (firstUpdated)
onAfterRender(changedProperties)After each render cycle (updated)
onDisconnected()Every DOM disconnection, after framework prop watchers and channel subscriptions are disposed.
onDestroy()Compatibility hook called by the default onDisconnected(); disconnection may be temporary.
onCacheHide()A cache-enabled route is hidden but remains connected. Pause work explicitly if needed.
onCacheView()A hidden cached route is restored. Not called for its initial mount.
Example
export class UserCard extends Okalit {
  onConnected() {
    console.log('Component mounted');
  }

  onChange(changes) {
    if (changes.userId) {
      console.log('User changed from', changes.userId.previous, 'to', changes.userId.current);
    }
  }

  onDisconnected() {
    console.log('Component unmounted');
  }
}

On reconnection, channels and prop watching are installed again; onFirstRender() does not repeat for the same instance. Setup must be repeatable and cleanup must release application-owned effects, timers, listeners and requests. Hidden cached routes remain active unless you pause them yourself.

Own the effects you create
onConnected() {
  this.stopEffect = effect(() => {
    console.log(this.count.value);
    return () => console.log('Cleaning up this effect run');
  });
}

onDisconnected() {
  this.stopEffect();
}

Prefer the new connection hooks. Overriding onConnected() or onDisconnected() replaces the default forwarding to legacy hooks; defining both names does not make both run automatically. Preserve super calls when extending an existing hook implementation, or when overriding native Lit lifecycle callbacks. Render hooks remain supported; they have not been removed.

output(name, detail)

Dispatches a CustomEvent with bubbles: false and composed: false. Listen directly on the child element. Use an explicit CustomEvent with the required options if delegation across Shadow DOM boundaries is intended.

Emitting events
// Inside a component method:
this.output('on:select', { id: 42 });

// Parent listens:
html`<child-el @on:select=${this.handleSelect}></child-el>`

Props System

@defineElement({ props }) is the only supported public input mechanism. Props are signals exposed through element accessors, with attribute-to-prop synchronization. Do not mix in Lit's static properties or @property decorators.

Defining Props

Declaration
@defineElement({
  tag: 'user-avatar',
  props: [
    { src:  { type: String, value: '' } },
    { size: { type: Number, value: 48 } },
    { online: { type: Boolean, value: false } },
  ]
})

Reading & Writing

Usage
// Read (inside render or effect):
this.size.value   // → 48

// Write (triggers re-render):
this.size.value = 64;

// Assign a raw value through the element setter:
this.size = 64;

// Parent template: property binding, not a signal object:
html`<user-avatar .size=${96}></user-avatar>`;

// From HTML attribute:
// <user-avatar size="96" online></user-avatar>

Attribute Coercion

When set via HTML attribute, values are automatically coerced:

  • String — used as-is
  • Number — parsed with Number(value)
  • Boolean — true if attribute exists and is not "false"

Attribute removal passes null through conversion: String becomes null, Number becomes 0, Boolean becomes false. There is no automatic prop-to-attribute reflection or JSON parsing. Pass objects and arrays with Lit property bindings such as .items=${items}, not serialized attributes. The type option controls attribute coercion, not runtime validation of property assignments.

Mixins (App, Module, Page)

Okalit provides three mixins that define the architectural layers of your application.

AppMixin

The root application component. Initializes router, i18n, and app-level config.

main-app.js
import { AppMixin, Okalit, defineElement, html } from '@okalit/core';
import routes from './app.routes.js';

@defineElement({ tag: 'main-app' })
export class MainApp extends AppMixin(Okalit) {
  static config = {
    routes,
    modeDebug: false,
    obfuscateChannels: true,
    i18n: { locales: ['en', 'es'], default: 'en', basePath: '/i18n' },
    template: (content) => html`<app-layout>${content}</app-layout>`,
  };
}
Config OptionTypeDescription
routesArrayRoot route definitions
modeDebugBooleanEnables channel debug logging
obfuscateChannelsBooleanScrambles channel data in storage
routerCacheLimitNumberMaximum hidden cached routes per root outlet (default 10). Set 0 to disable retention.
i18nObjecti18n configuration (locales, default, basePath)
templateFunctionLayout wrapper for the router outlet

ModuleMixin

Groups related pages under a feature boundary. Provides a nested <okalit-router> for child routes.

AppMixin destroys its router and clears outlet registrations on disconnection, then recreates the router on reconnection. Apply it to a single application root. For a ModuleMixin outlet, configure static routerCacheLimit = 10 on the module class.

home.module.js
import { ModuleMixin, Okalit, defineElement } from '@okalit/core';

@defineElement({ tag: 'home-module' })
export class HomeModule extends ModuleMixin(Okalit) {}

PageMixin

Routed view components. Provides route params, query params, and navigation helpers.

home.page.js
import { PageMixin, Okalit, defineElement, html } from '@okalit/core';

@defineElement({ tag: 'home-page' })
export class HomePage extends PageMixin(Okalit) {
  onCacheHide() {
    // It is called when the page is hidden and the route has the `cache` parameter set to `true`.
  }

  onCacheView() {
    // It is called when the page is displayed and the route has the `cache` parameter set to `true`.
  }

  render() {
    return html`<h1>Welcome home</h1>`;
  }
}

Router

Built-in SPA router with lazy loading, nested routes, dynamic params, and navigation guards.

Route Definition

app.routes.js
export default [
  {
    path: '/',
    component: 'home-module',
    import: () => import('./modules/home/home.module.js'),
    children: [
      {
        path: '',
        component: 'home-page',
        import: () => import('./modules/home/pages/home.page.js'),
      },
      {
        path: '/users/:id',
        component: 'user-page',
        import: () => import('./modules/home/pages/user.page.js'),
      },
    ],
  },
  {
    path: '/admin',
    component: 'admin-module',
    import: () => import('./modules/admin/admin.module.js'),
    guards: [authGuard],
    children: [...],
  },
];

Route Config Object

FieldTypeDescription
pathstringURL pattern. Supports :param dynamic segments and a trailing ** catch-all.
componentstringCustom element tag to render
importFunctionLazy loader (dynamic import)
childrenRoute[]Nested child routes
guardsFunction[]Navigation guards (run before loading)
cacheBooleanOpt in to retaining the route element while hidden. Omitted or false removes it when leaving.

Not-found pages and wildcard routes

Add a trailing ** route to render your own 404 page when no specific sibling route matches. Specific routes take priority even when the wildcard is declared first.

app.routes.js — application-wide fallback
export default [
  {
    path: '/home',
    component: 'home-page',
    import: () => import('./pages/home.page.js'),
  },
  {
    path: '**',
    component: 'not-found-page',
    import: () => import('./pages/not-found.page.js'),
  },
];

A wildcard can also be scoped to a module. It handles unknown child paths under that module without catching paths belonging to other modules:

admin.routes.js — module fallback
children: [
  {
    path: '/users',
    component: 'admin-users-page',
    import: () => import('./users.page.js'),
  },
  {
    path: '**',
    component: 'admin-not-found-page',
    import: () => import('./not-found.page.js'),
  },
]

The wildcard must be the final path segment. It does not capture the unmatched URL as a route parameter. A root-level wildcard is optional; without one, unmatched paths continue to be reported as having no matching route.

Route lifetime and optional cache

By default, leaving for another route component removes the old element. Its disconnect hook runs and a later visit creates a new instance. Cache is opt-in per route: it retains the element and its local DOM/state, hiding it with display: none.

Retain an editor; recreate other pages
export default [
  {
    path: '/editor',
    component: 'editor-page',
    import: () => import('./editor.page.js'),
    cache: true,
  },
  {
    path: '/summary',
    component: 'summary-page',
    import: () => import('./summary.page.js'),
  },
];

// Inside EditorPage: these hooks do not disconnect/reconnect the element.
onCacheHide() { this.pausePreview(); }
onCacheView() { this.resumePreview(); }

Each outlet retains at most 10 hidden routes by default. Configure routerCacheLimit on AppMixin's config, static routerCacheLimit on a module, or <okalit-router cache-limit="5"> on a custom outlet. Eviction removes the oldest hidden entry and triggers disconnection. Hidden routes do not automatically stop effects, subscriptions, timers or requests.

The current outlet identifies active and cached views by component tag, not by the full URL. Navigating between parameters of the same component reuses that instance even without cache: true; react to route state rather than relying only on connection hooks. Caching a page also does not exempt scoped channels from router cleanup.

Initial navigation and visual flashes

Resolve session redirects in guards before mounting a login page, rather than redirecting from its connection hook. When changing modules, the outlet prepares the incoming element hidden and waits for its first render and the matched nested route before revealing it and removing or hiding the outgoing view. This avoids an empty intermediate view, but is not an animated transition; updateComplete does not mean that network data or images have loaded.

Navigation Guards

Guards are async functions that control route access. They can allow, block, or redirect.

auth.guard.js
export function authGuard({ path, params, route }) {
  const token = getChannel('session:token')?.value;

  if (!token) return '/auth/login'; // redirect
  return true;                         // allow
  // return false;                      // block silently
}

Programmatic Navigation

Usage
// Inside any component with PageMixin or ModuleMixin:
this.navigate('/users/42');
this.navigate('/login', { replace: true });
this.backRoute();

// From anywhere (helper function):
import { navigate } from '@okalit/core';
navigate('/dashboard');

Channel Scopes & Router

The router automatically clears scoped channels on navigation:

  • scope: 'page' — cleared when navigating to a different page
  • scope: 'module' — cleared when navigating to a different module
  • scope: 'app' — never cleared automatically

Channels (Global State)

Channels provide reactive, cross-component state management without prop-drilling. They support persistence, scoping, validation, and pub/sub patterns.

Defining a Channel

session.channel.js
import { defineChannel } from '@okalit/core';

export const sessionToken = defineChannel('session:token', {
  initialValue: null,
  persist: 'local',     // 'memory' | 'local' | 'session'
  scope: 'app',         // 'app' | 'module' | 'page'
});

export const userProfile = defineChannel('session:user', {
  initialValue: { name: '', email: '', avatar: '' },
  persist: 'local',
  scope: 'app',
  validate: (value) => value && typeof value.email === 'string',
});

// Ephemeral channel (event bus, no state stored)
export const toastEvent = defineChannel('ui:toast', {
  ephemeral: true,
  scope: 'app',
});

Channel Options

OptionDefaultDescription
initialValue—Default value (ignored if ephemeral)

Using Channels in Components

Handles declared in static channels are installed on connection, after subclass construction finishes and before onConnected(). They are not available in the constructor or eager field initializers. Stateful callbacks run initially on connection and subsequently on changes; all handles are installed before these initial callbacks run. Framework subscriptions are disposed on disconnection and recreated on reconnection.

profile.page.js
import { sessionToken, userProfile, toastEvent } from '../../channels/session.channel.js';

@defineElement({ tag: 'profile-page' })
export class ProfilePage extends PageMixin(Okalit) {
  // Declare channels with optional method callbacks
  static channels = {
    token: sessionToken(),                    // read/write handle
    user: userProfile('onUserChange'),        // + subscribe to changes
    toast: toastEvent('onToast'),             // ephemeral subscription
  };

  onConnected() {
    console.log('Current user:', this.user.value);
  }

  onUserChange(value) {
    console.log('User updated:', value);
  }

  onToast(message) {
    // Show toast notification
  }

  render() {
    return html`
      <p>Hello, ${this.user.value?.name}</p>
      <button @click=${() => this.user.set({ ...this.user.value, name: 'New' })}>
        Update name
      </button>
      <button @click=${() => this.toast.set('Profile saved!')}>
        Show toast
      </button>
    `;
  }
}

Reading Channels Outside Components

auth.guard.js
import { getChannel, getChannelValueStorage } from '@okalit/core';

// Read from active channel (runtime)

// Read directly from storage (before channels are initialized)

Imperative subscribeChannel(name, callback) returns { handle, dispose }; call its disposer yourself. Browser storage and channel obfuscation are not a security boundary: obfuscation is reversible, not encryption. Do not treat stored session values as proof of authorization; the server must enforce access control. Storage availability and quota errors still need application-level handling.

Forms & Validation

Okalit includes a reactive form system with built-in validators, powered by signals.

Creating a Form

login.page.js

const form = createForm({
  fields: {
    email:    { value: '', validators: [required(), isEmail()] },
    password: { value: '', validators: [required(), minLength(8)] },
  },
  validateOn: 'blur',  // 'input' | 'blur' | 'submit'
});

Disposal and reconnection

validateOn: 'input' installs effects when the form is created. Dispose them when their owner disconnects. A disposed form does not automatically resume input validation on reconnection; recreate it if that is the desired lifetime. Blur/submit forms do not create these automatic effects. Hidden cached routes remain connected, so they do not dispose their forms merely by being hidden.

Connection-scoped input validation
onConnected() {
  this.form = createForm({
    fields: {
      title: { value: '', validators: [required()] },
    },
    validateOn: 'input',
  });
}

onDisconnected() {
  this.form.dispose();
}

This example intentionally resets the form after reconnection; retain a separate draft if values must survive. For native inputs, adapt their events to the form API or write the field signal directly. handleInput expects event.detail.name and event.detail.value, not a native input event's target.

Full Form Example

register.page.js
import { createForm, required, isEmail, minLength, match } from '@okalit/core/form';

form = createForm({
  fields: {
    email:    { value: '', validators: [required(), isEmail()] },
    password: { value: '', validators: [required(), minLength(8)] },
    confirm:  { value: '', validators: [
      required(),
      match(() => this.form.fields.password.value.value, 'Passwords do not match'),
    ]},
  },
});

handleSubmit() {
  if (!this.form.validate()) return;

  inject('auth').register(this.form.values()).fire({
    onSuccess: () => this.navigate('/home'),
    onError: (err) => this.form.setErrors(err.body),
  });
}

render() {
  const { email, password, confirm } = this.form.fields;
  return html`
    <input-atom name="email"
      .value=${email.value.value}
      .error=${email.error.value}
      @on:change=${this.form.handleInput}
      @on:blur=${this.form.handleBlur}></input-atom>

    <button-atom
      .disabled=${!this.form.valid.value}
      @on:click=${this.handleSubmit}>Register</button-atom>
  `;
}

Services & Dependency Injection

Services are singleton classes registered via the @service decorator and retrieved with inject(). They encapsulate API calls and business logic.

The Pattern

auth.service.js
import { OkalitService, service, inject } from '@okalit/core';

@service('auth')
class AuthService extends OkalitService {
  constructor() {
    super();
    this.configure({
      baseUrl: 'https://api.example.com',
    });
  }

  login(credentials) { return this.post('/auth/login', credentials); }
  register(data)     { return this.post('/auth/register', data); }
}

// Usage anywhere:
inject('auth').login({ email, password }).fire({
  onLoading: (v) => ...,
  onSuccess: (data) => ...,
  onError: (err) => ...,
});

RequestControl

All service methods return a RequestControl — a thenable wrapper that supports both declarative (.fire()) and imperative (await) patterns:

fire() currently returns undefined, not the request promise. To await completion and handle errors with try/catch, await the RequestControl itself. Component disconnection or route caching does not automatically cancel service calls or suppress late responses.

Two usage patterns
// Pattern 1: Declarative with .fire()
inject('posts').getAll().fire({
  onLoading: (loading) => this.loading.value = loading,
  onSuccess: (data) => this.posts.value = data,
  onError: (err) => this.error.value = err.message,
  onFinish: () => console.log('done'),
});

// Pattern 2: Imperative with await
const data = await inject('posts').getAll();

Interceptors

Interceptors modify requests before they're sent or responses after they're received.

Bearer token interceptor
this.configure({
  interceptors: [
    ({ url, options }) => {
      const token = getChannel('session:token')?.value;
      if (token) {
        options.headers['Authorization'] = `Bearer ${token}`;
      }
      return { url, options };
      // return null; → cancels the request
    }
  ],
  responseInterceptors: [
    ({ data, error }) => {
      if (error?.status === 401) {
        navigate('/auth/login');
      }
      return { data, error };
    }
  ],
});

WebSocket Service

Full-featured WebSocket client with auto-reconnect, exponential backoff, keepalive pings, and message interceptors.

chat.socket.js
import { OkalitSocketService, service } from '@okalit/core';

@service('chat')
class ChatService extends OkalitSocketService {
  constructor() {
    super();
    this.configure({
      url: 'wss://ws.example.com/chat',
      reconnect: true,
      reconnectInterval: 2000,
      reconnectMaxInterval: 30000,
      maxReconnectAttempts: 10,
      pingInterval: 30000,
    });
  }

  async join(roomId) {
    await this.connect();
    await this.send('join', { roomId });
  }

  sendMessage(roomId, text) {
    this.send('message', { roomId, text });
  }

  onNewMessage(callback) {
    return this.on('message', callback);
  }

  leave() { this.disconnect(); }
}

Lazy Loading Elements

Okalit provides three custom elements for deferred loading of heavy components, optimizing initial bundle size and perceived performance.

<o-idle> — Load on Browser Idle

Loads content when the browser is idle (via requestIdleCallback). Falls back to a 200ms timeout.

Usage
const idle = document.querySelector('o-idle');
idle.loader = () => import('./heavy-chart.js');

<!-- In HTML: -->
<o-idle>
  <heavy-chart></heavy-chart>
  <span slot="fallback">Loading chart...</span>
</o-idle>

<o-when> — Load on Condition

Loads content when a boolean condition becomes true.

Usage
const el = document.querySelector('o-when');
el.loader = () => import('./admin-panel.js');
el.condition = user.isAdmin; // loads only when true

<o-viewport> — Load on Scroll into View

Loads content when the element enters the viewport (via IntersectionObserver, with 200px root margin).

Usage
const el = document.querySelector('o-viewport');
el.loader = [
  () => import('./comments-section.js'),
  () => import('./comment-item.js'),
];

<!-- In HTML: -->
<o-viewport>
  <comments-section></comments-section>
  <div slot="fallback">
    <skeleton-loader></skeleton-loader>
  </div>
</o-viewport>

Common Behavior

  • loader accepts a function or array of functions (resolved with Promise.all)
  • Adds [loaded] attribute when complete — default slot shown, fallback hidden
  • Dispatches o-error event (bubbles + composed) on failure
  • Loads only once — subsequent reconnections don't re-trigger

Status & Future Work

This documentation describes the local Core 0.3.0 implementation, not a guarantee of registry publication or a completed stability/security audit. Lit is the current rendering foundation; a renderer-independent or vanilla implementation is not shipped.

Implemented in this line

  • Lit 3 rendering with SignalWatcher; local signal wrappers preserving .value; no uhtml dependency or batch export.
  • Decorator props as the supported input contract; channel setup after construction; repeatable connection/disconnection hooks with legacy forwarding.
  • Router outlet registration cleanup and app router recreation; optional, bounded route cache with hide/restore hooks.
  • Explicit form effect disposal through form.dispose().

Stabilization priorities, not completed features

  • Browser regression tests for DOM identity, focus, props, channels, reconnects, route cache and navigation races. Existing Node tests and builds do not verify all browser behavior.
  • A consistent async error/cancellation contract, including disposal during lazy route imports, service callback errors and late results.
  • More resilient storage access, explicit persisted-data versioning/migration and documented failure handling.
  • An atomic visual route swap to reduce transition flashes. The existing first-render wait is not a complete solution.

Optional integrations under consideration

Async resources or @lit/task, tree-scoped dependencies with @lit/context, virtualized lists, and an RxJS adapter are proposals, not built-in APIs. React wrappers, scoped registries, SSR and a possible vanilla experiment also require separate compatibility work. Zustand and another Signals implementation are not required for current state management.

Application safety still requires server-side authorization and validation, appropriate handling of browser storage and untrusted content, and GraphQL variables rather than user-input interpolation. Lit text interpolation is not a general sanitizer for arbitrary HTML, URLs, CSS or scripts; the gql helper is not a sanitizer either.
